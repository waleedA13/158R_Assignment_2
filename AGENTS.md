# AGENTS.md

Instructions for every coding agent working in this repo. Waleed and Aditya both maintain this file.
Every agent prompt in the GitHub issues starts with "Read AGENTS.md and HANDOFF.md first", because nothing loads this file automatically.

## Read first
1. `HANDOFF.md`: project state, assumptions, protocol, session log.
2. `ISSUES.md`: the issue you are working on (find it by its `[I-NN]` ID).
3. `docs/decision.md` (once it exists): dataset, task, metrics, models. Do not contradict it.

## Hard rules
- **No AI attribution anywhere.** Never mention any AI assistant, model or tool by name in commits, PRs, issues, code, comments, notebooks, docs, slides or file names. No co-author trailers, no "generated by" footers, no session links. If you must refer to yourself in a log, write "agent".
- **Writing style:** no em dashes or en dashes. Use colons, commas, periods, or "to" for ranges.
- **Stay in scope:** only touch files your issue names. Never edit a notebook owned by the other person.
- **One split, one metric module:** always use `src/data.split()` and `src/metrics.py`. Never touch the test set outside I-12/I-13.
- **No invented facts:** no made-up results, numbers, dataset details or citations. Every number must come from code in this repo.
- **Human-only work:** issues labelled `owner:human` (slides wording, video narration, peer grading, uploads) are written and done by people. Agents may only check numbers or run tooling for them. The rubric scores auto-generated presentations 1/5.

## Workflow
- Branch: `i<NN>-<slug>` from up-to-date `main`. Commit: `[I-NN] imperative message`.
- Before committing notebooks drafts: `jupyter nbconvert --clear-output --inplace notebooks/*.ipynb`.
- Open a PR titled `[I-NN] ...`; the other person reviews. Squash-merge.
- Verify before saying done: run the commands in the issue's prompt and paste their output in the PR.
- End of session: follow the checklist in `HANDOFF.md` section 6.
